# BreezyVoice 中英夾雜配音規則

本指南整理 2026-10-25 至 2026-10-26 自我介紹配音的實際微調經驗。目標是從正常繁中稿，以本機 BreezyVoice 生成自然的個人聲音。英文名稱、正確字音、連續語流與前後語氣一起驗收；每份新稿均需試聽。

## 先用固定參考生成新文字

1. 準備使用者有權使用的乾淨參考錄音與精確逐字稿。可沿用先前已核准、無配樂的個人聲線／風格片段，建議 5–15 秒，支援 3–30 秒。
2. 正常定稿保留正式名稱及標點。另建本片讀音字典；依語境選取 [範例字典](../examples/pronunciation-code-switching.json) 中的規則。
3. 先產生含中英名稱、數字及問題詞的完整短句，連同前後句試聽，再生成完整旁白。所有新內容先由本機 BreezyVoice 產生。
4. 同文 Fish 合成僅按使用者明確指定進行。固定核准參考可持續重用，後續每份新稿都從本機生成流程開始。

在自己的工作目錄建立字典，並從倉庫根目錄執行：

```sh
cp examples/pronunciation-code-switching.json work/my-reel/pronunciation.json
# 按這份新稿刪減或調整問題詞，保留原始正常稿。
.runtime/breezy/env/bin/python magicreels/tts.py \
  --text '大家好，我是 Bill。我用 Codex，串起腳本、配音與配樂。' \
  --runtime .runtime/breezy \
  --reference work/my-reel/reference.wav \
  --reference-text work/my-reel/reference.txt \
  --pronunciations work/my-reel/pronunciation.json \
  --out work/my-reel/preview-v1
```

環境、自己的參考檔與工作目錄先按 [安裝與基本操作](breezyvoice.md) 準備。每次換新輸出目錄；本指南不附個人參考聲音。

## 文字與拼讀分開保存

中文原字保留，只在問題字後加入注音；英文拼讀別名限定單一英文字母單字，按大小寫與完整名稱邊界替換。例如：

```json
{
  "Bill": "bill",
  "Codex": "CodeX",
  "配音": "配[:ㄆㄟ4]音[:ㄧㄣ1]",
  "實作": "實[:ㄕ2]作[:ㄗㄨㄛ4]"
}
```

`CodeX` 是 Code 接 X 連讀的試聽輸入；先前的 `codes` 試法已撤回。`Bill → bill` 曾用於降低名字開頭的強調。別名效果依聲線與上下文試聽。`Bill2`、`BillGates`、`CodexAPI` 等不同名稱保留原樣；含空白、數字或標點的英文別名會被拒絕。

`display-script.txt` 與字幕保留 Bill、Codex 等原名；`synthesis-input.txt` 及 `pronunciation-map.json` 保存實際替換結果。以較長詞優先、單次替換，避免替換結果再次被套規則。Fish 的替代字與音素規則各自管理。

### 實際遇過的問題詞

| 字詞 | 目標／候選處理 | 試聽重點 |
| --- | --- | --- |
| 大家好 | 好 `ㄏㄠ3` | 三聲及整句連讀，避免像大家豪。 |
| Bill | 合成別名 `bill` | 開頭輕帶，保留使用者確認的名字讀法；本例期望接近「必有」。 |
| Codex | 合成別名 `CodeX` | Code 與 X 相連，避免讀成 Cardex 或兩個分離詞。 |
| 串起 | 串 `ㄔㄨㄢ4`、起 `ㄑㄧ3` | 串的聲調，避免像穿起。 |
| 配音 | 配 `ㄆㄟ4`、音 `ㄧㄣ1` | 配的四聲、詞內銜接，避免像培因。 |
| 配樂 | 配 `ㄆㄟ4`、樂 `ㄩㄝ4` | 配的四聲，避免像培月。 |
| 成為 | 為 `ㄨㄟ2` | 保留本詞多音字語境。 |
| 分享 | 分 `ㄈㄣ1` | 整詞聲調、音質與銜接，避免分與享被拆散。 |
| 實作 | 實 `ㄕ2`、作 `ㄗㄨㄛ4` | 完整韻母與句內節奏，避免作讀成 ㄗㄨˋ。 |

以上是案例中的修正候選，範例字典供逐詞選用。預設字典為空；新語境用短段確認後再採用。大量逐字注音可能拉長音節或拆散語流，持續有問題時升到整句處理。

## 停頓與語氣的處理順序

1. **依語意斷句。** 過多逗點與短句可能形成喘促感。先調整合成稿的標點與語意分段，顯示稿保留核准文字；公開 CLI 的正常稿也作為字幕來源，若另試標點版本，需由製作者核對正常稿與音訊映射。
2. **以完整句測讀音。** 單獨生成兩個字可能出現額外音節或不合語境的停頓。先用含前後詞的句子試聽。
3. **修訂涵蓋完整語意句。** 詞級波形補字若形成空隙、重音突變或接點，就重建整句；保留範圍外已核准音訊與版本。
4. **同時比對前後語氣。** 正確字音之外，檢查語速、重音、氣口、音高走勢與音量強弱。僅把音色轉成同一人，仍可能帶入偏柔和的表現。
5. **匹配後再接回。** 先用固定增益匹配新舊句響度，再評估語氣；必要時用有對時的音量輪廓輔助。保留峰值餘裕、平滑及低音量區保護，避免把噪音拉高。

參考錄音、內容語音單元與音量輪廓各影響不同面向。固定風格參考要接近希望成品的自然敘述語氣，逐字稿精確相符；新文字另用自身實際時間碼。

## 微調過程與進階方法紀錄

| 階段 | 觀察 | 得到的規則 |
| --- | --- | --- |
| v1–v3 | 好、串、配與英文名稱讀音有誤，名字重音偏強，停頓過多 | 正常稿／合成稿分開；以詞級注音、英文別名與語意斷句試聽。 |
| Fish 對照與 v4 | 一次同文 Fish 對照的節奏較合意；只換參考錄音的 Breezy 直接 TTS 仍有語流問題 | 固定參考錄音能影響風格，內容單元也帶有節奏。 |
| v5 | 既有對照的語音單元經 Bill 聲線的 CFM 與 vocoder 重建，匹配 RMS 輪廓後效果獲確認 | 同文內容單元能保留表現；這份舊前段有 Fish 衍生來源。 |
| v6 | 使用固定核准參考，直接由本機生成參考未說過的後兩句；仍有少數問題詞 | 用新文字驗證獨立生成，逐詞及全句試聽。 |
| v7 | 字音修正後，詞級波形剪接造成實作前後停頓 | 調整單位提升到完整語意句，並保留其他核准區間。 |
| v8 | 整句重建改善連貫，語氣變得偏柔 | 官方範例等內容來源的表現也可能進入新句，需比對前後風格。 |
| v9 | 保留本機早期直接讀法的節奏，在單元層修正作，用核准前段作風格參考，整句 CFM 重建並匹配音量輪廓，完整旁白獲使用者確認 | 字音、語流及前後語氣一起驗收；本機後續生成與修訂未新增 Fish 請求。 |

研究用的 RMS 起點為 40 ms 視窗、10 ms hop、30 ms 平滑；同文移轉曾用 ±6 dB 限制，整句局部修訂縮到 ±3 dB，並使用 -42 dB quiet gate。每次需按實際對時、底噪與峰值調整。不同內容可參考一般節奏與強弱，新句須重新對時；舊句的時間碼與 token 區間僅適用原句。

公開 CLI 支援直接 Breezy TTS、中文注音與英文拼讀字典。語音單元抽換、CFM 整句重建及同文 RMS 匹配目前記錄為進階研究方法，尚未提供通用自動修補命令；任意新稿的品質仍以實際試聽判斷。可參考 [BreezyVoice 官方程式](https://github.com/mtkresearch/BreezyVoice)與[語音單元方法的論文說明](https://arxiv.org/html/2501.17790v1#S6.SS1.SSS3)。

## 完整音軌驗收與接回影片

- 聽完整旁白，確認人名、英文、聲調、停頓、連讀與整體語氣；同時比較被修訂句的前後文。
- ASR 用來定位可能的錯字與時間，RMS 與基頻用來比較；實際核准由使用者試聽決定，綁定音檔 hash。
- 檢查全片解碼、削波、接點、音量及實際時長；局部修訂可逐樣本確認範圍外音訊。
- 使用正常稿與當次 `audio-map.json` 對時。新版本重建實際字幕與分鏡邊界，保留既有核准版本。
- 完整音軌確認後，按 [製作指南](workflow.md) 記錄 `approval.json` 並合成影片；配樂在聲音確認之後加入。
